# 녹화 영상 머리 분석 — 5초 간격

시연 입력은 **아이폰 17로 녹화한 영상 파일**이며, **Mac M4에서 분석**합니다. 결과를 보여주는 서비스 앱은 Android입니다. 현재 구현은 로컬 영상 파일을 읽어 상세 JSON을 생성하는 AI CLI까지입니다. 업로드 화면, 업로드 API, DB 저장, 백엔드 전송, 영상과 결과의 재생 동기화는 구현하지 않았습니다.

## 촬영과 실행

- 아이폰 기본 카메라에서 후면 카메라·가로 방향으로 촬영하고 위치와 구도를 고정합니다.
- 최초 연결 확인은 1080p 영상으로 시작합니다. 실제 식당의 먼 머리를 구분할 수 있는 해상도인지는 별도로 검증합니다.
- 사람이 들어오고 나가는 장면을 담아 5초 단위 결과 변화를 확인합니다.
- MP4/MOV 파일을 Mac으로 옮긴 뒤 로컬 파일 경로를 입력합니다. 파일 확장자만으로 코덱 호환이 보장되지 않으며, 전달된 실제 아이폰 영상은 별도 확인이 필요합니다.

저장소 루트에서 실행합니다. 아래 영상 경로는 실제 파일 경로로 바꿉니다. 출력 디렉터리는 먼저 만들고 출력 파일은 새 이름을 사용합니다.

```bash
source .venv/bin/activate
mkdir -p runs/head/video_demo
python ai/predict_head_video.py \
  --model runs/head/indoor_hardneg_20261106_01/weights/best.pt \
  --source "/실제/영상/경로/cafeteria.mov" \
  --output runs/head/video_demo/heads.json \
  --interval 5 \
  --tile-size 2048 --tile-overlap 0.2 \
  --imgsz 1280 --conf 0.10 --iou 0.7
```

`--interval`을 생략해도 기본값은 **5초**입니다. 기본 장치는 MPS이며 CPU는 `--device cpu`로 명시합니다. 위 모델과 타일 설정은 [후속 식당 사진 비교](head_extension_20261106.md)에서 선택했습니다. 타일은 원본 픽셀 기준 2048이고 모델 입력은 1280입니다. CLI에서 타일 옵션을 생략하면 전체 프레임 추론이 되므로 주의합니다. 실제 영상의 해상도·화질에서 정확도와 처리 시간을 별도로 확인해야 합니다. 현재 설정은 독립 현장 테스트를 통과한 배포 모델이 아닙니다.

간격은 **영상 내 시간**입니다. 0초, 5초, 10초 등의 경계에 도달한 첫 프레임을 선택합니다. 프레임 시각이 경계와 정확히 일치하지 않으면 실제 선택 시각을 기록합니다. 분석 프로그램이 매번 실제 시간 5초를 기다리는 방식은 아닙니다. 5초 미만 영상도 첫 프레임 한 건은 분석합니다.

## 결과 형식

`head-video-v1`은 기존 사진 결과의 `images[]` 및 `head_count`, `detections` 구조를 유지합니다. 각 항목은 선택한 영상 프레임 한 장입니다.

| 필드 | 의미 |
| --- | --- |
| `schema_version` | `head-video-v1` |
| `input_type` | `recorded_video`. 녹화 분석 결과를 실시간 관측과 구분 |
| `video_name` | 입력 영상 파일명. 업로드 시스템의 고유 영상 ID를 대신하지 않음 |
| `model_file` | 사용한 로컬 모델 경로 |
| `sample_interval_seconds` | 기본 `5` |
| `timestamp_source` | `decoder_relative_to_first_frame`: 디코더 시각에서 첫 프레임 시각을 뺀 값 |
| `reported_fps` | 디코더가 보고한 FPS. 가변 FPS 영상의 정확한 시각 계산에는 사용하지 않음 |
| `images[].frame_index` | 성공적으로 읽은 프레임의 0부터 시작하는 순번 |
| `images[].video_time_seconds` | 영상 시작 기준 상대시각. 실제 촬영 날짜·시각이 아님 |
| `images[].image_name` | `영상명#frame=번호` 형태의 프레임 식별 문자열. 별도 이미지 파일을 생성하지 않음 |
| `images[].image_width`, `image_height` | 회전 메타데이터를 적용해 읽은 프레임 크기 |
| `images[].head_count` | 해당 프레임에서 탐지한 머리 수 |
| `images[].detections` | 기존 `name`, `class`, `confidence`, `box` 상세 결과 |
| `reported_frame_count` | 영상 메타데이터가 보고한 프레임 수. 알 수 없으면 `null` |
| `decoded_frame_count` | 실제 읽은 전체 프레임 수 |
| `analyzed_frame_count` | 선택해 모델로 분석한 프레임 수 |
| `last_decoded_video_time_seconds` | 마지막으로 읽은 프레임 시각. 정확한 영상 전체 길이를 의미하지 않음 |
| `decode_check` | `frame_count_matched` 또는 `end_not_verified_by_frame_count` |
| `analyzed_at` | 결과 생성 시각, UTC ISO 8601. 촬영 시각과 구분 |

`head_count == len(detections)`이며, 여러 프레임의 인원 수를 더해 총 방문자 수나 좌석 점유 수를 만들지 않습니다. 모델의 누락·오탐은 별도 평가가 필요합니다.

## 오류와 출력 파일

- 빈 영상, 읽기 실패, 시각 누락·반복·역행은 0명 결과로 바꾸지 않습니다.
- 보고된 프레임 수보다 일찍 디코딩이 끝나면 오류로 중단합니다. OpenCV만으로 모든 파일 손상과 정상 종료를 완벽히 구별할 수는 없습니다.
- 보고된 프레임 수가 없거나 실제 수와 다르면 `end_not_verified_by_frame_count`로 표시합니다. `frame_count_matched`도 탐지 정확도나 모든 픽셀의 무결성 보증은 아닙니다.
- 처리 중에는 임시 파일에 결과를 기록하고, 완료 후에만 지정한 JSON 파일을 게시합니다. 오류가 나면 임시 결과를 정리하며 기존 결과 파일을 덮어쓰지 않습니다.
- 원본 영상·프레임을 외부로 전송하거나 추가 저장하지 않습니다. 모델 다운로드도 수행하지 않습니다.

## 현재 검증 범위

자체 생성한 MP4 테스트 영상(10 FPS, 121프레임)을 기존 로컬 모델로 MPS에서 실행했습니다. 프레임 0·50·100, 즉 영상 내 0·5·10초가 선택되었고 상세 JSON 3건이 생성됐습니다. 사람이 없는 테스트 영상이므로 이 검증은 영상 입력·샘플링·추론·파일 출력 경로의 동작 확인이며 탐지 정확도 평가가 아닙니다.

불규칙 프레임 시각, 빈 입력·중간 종료·잘못된 시각 처리, 기존 출력 파일 보호와 실패 시 임시 파일 정리도 통과했습니다. 별도 CPU 검토에서 기존 사진 출력 형식의 회귀가 없음을 확인했습니다. 실제 아이폰 MOV/HEVC 영상의 디코딩·회전과 식당 머리 탐지 정확도는 사용자가 제공할 영상에서 추가 검증해야 합니다.
