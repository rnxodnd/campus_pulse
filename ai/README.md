# AI 담당 작업 안내

대상은 **5공학관 식당 한 곳, 총 300석**입니다. 영상에서 인원을 추정하고 좌석별 상태를 판단해 백엔드에 전달합니다. 인원 수와 좌석 점유는 별도 결과입니다.

이 폴더에는 현재 작업 안내만 있으며, 탐지·좌석 분류·추적·결과 전송 코드는 없습니다. 아래 API 필드와 세부 분담은 **합의 제안이며 미구현**입니다.

- 전체 범위: [프로젝트 README](../README.md)
- 학습 환경과 명령 안내: [Mac 학습 안내](../docs/training_mac.txt)
- 결과 수신·저장 연계: [백엔드 담당 안내](../backend/README.md)

## 담당 범위와 두 사람의 분담

초안상 AI 담당자는 **변민석·구태웅 2명**입니다. 작업 A/B를 누가 맡을지는 아직 정하지 않았습니다.

| 작업 | 담당할 내용 | 공유할 결과 |
| --- | --- | --- |
| A: 머리 탐지·외부 데이터 | 데이터 적합성 확인, 라벨 변환, 장면별 데이터 분리, 머리 모델 학습·평가, 인원 추정 | 데이터 구성 기록, 모델·설정, 머리 탐지 결과와 인원 오차 |
| B: 좌석 분류·시간 상태 | 좌석 영역과 ID 정의, 사람·짐·빈자리 구분, 가림 처리, 일시 비움 후보 판단 | 좌석 배치 정보, 상태 판정 규칙, 좌석별 결과와 오류 사례 |
| 공동 | 영상 입력 연결, 결과 형식 합의, 실제 장소 검증, 처리 지연 측정 | 백엔드 전달 결과, 통합 시연, 검증 기록 |

머리 모델이 완성되기 전에도 B는 좌석 정의와 라벨 기준을 준비할 수 있습니다. A/B 모두 동일한 영상·좌석 ID·관측 시각을 기준으로 결과를 연결합니다.

## 우선 작업 순서

1. **영상 입력과 분석 범위 확정**
   - 실시간 영상이 AI 분석 서버까지 들어오는 구조를 정합니다. 서버 위치와 영상 프로토콜은 미정입니다.
   - 실제 카메라 수·고정 구도·관측 구역을 확인합니다. 제공된 네 방향 사진을 카메라 네 대로 가정하지 않습니다.
2. **좌석 목록과 현장 정답 준비**
   - 전체 300석에 고유한 `seat_id`를 부여하고 관측 가능한 좌석 영역을 연결합니다.
   - 여러 영상에 보이는 같은 좌석은 하나의 ID를 사용합니다. 관측하지 못하는 좌석은 `unknown`으로 남깁니다.
   - 사람·짐·고정 비품·빈자리·가림 사례를 직접 확인해 라벨 기준을 맞춥니다.
3. **머리 학습 데이터 적합성 확인**
   - [AI-Hub 71368 실내외 군중 특성 데이터](https://www.aihub.or.kr/aihubdata/data/view.do?aihubDataSe=data&dataSetSn=71368)의 **2세부 머리 bbox 데이터는 후보**입니다.
   - 실제 파일 구조와 머리 박스를 확인한 뒤 YOLO 형식 변환 여부를 결정합니다. 1세부의 점 좌표에 임의 크기 박스를 붙여 정답으로 쓰지 않습니다.
   - 영상·장면 또는 충분히 떨어진 시간 구간별로 train/val/test를 나눕니다. 인접 프레임을 서로 다른 묶음에 섞지 않습니다.
4. **작은 학습·추론부터 점검**
   - M4에서 짧게 실행해 데이터·MPS·저장을 확인한 후 실제 측정값으로 학습 범위를 정합니다.
   - 모델과 데이터 양이 정해지기 전에 학습 시간이나 정확도를 보장하지 않습니다.
5. **좌석 상태와 시간 규칙 검증**
   - 아래 상태 정의에 맞춰 좌석별 결과를 만들고, 일시 비움 후보의 신뢰도와 유지 정책을 합의합니다.
   - 아직 합의하지 않은 시간값이나 추적 규칙을 확정 정책으로 넣지 않습니다.
6. **백엔드 연동 후 현장 평가**
   - 먼저 공통 결과 형식을 맞추고, 실제 분석 결과로 바꿔 전달합니다.
   - 머리 탐지·좌석 상태·전송 지연을 각각 확인합니다.

## 좌석 상태 판정 원칙

한 좌석은 한 관측 시점에 다음 **다섯 상태 중 하나**만 가집니다.

| 상태 | 의미와 판정 조건 |
| --- | --- |
| `available` | 관측 가능한 좌석에 사람·점유하는 짐이 없고 이용 가능하다고 판단한 상태 |
| `person_occupied` | 사람이 사용 중인 좌석. 같은 좌석에 짐도 있어도 이 좌석은 한 번만 계산 |
| `belongings_occupied` | 사람은 없지만 해당 좌석을 짐이 차지하는 상태 |
| `temporarily_away` | 사용 이력과 신뢰할 수 있는 추적 등 합의한 증거·운영 기준을 충족해 일시 비움으로 판단한 좌석 |
| `unknown` | 사각, 가림, 상충하는 감지 결과, 근거 부족 등으로 판단할 수 없는 상태 |

- **가방을 들고 배식하거나 이동하는 사람만으로 좌석을 점유 처리하지 않습니다.** 기존 좌석 사용 이력이 없으면 그 관측으로 배정할 점유 좌석은 0개입니다.
- 기존 사용 이력이 있더라도 일시 비움 후보 자체를 `temporarily_away`로 처리하지 않습니다. 합의한 조건을 충족하지 못하거나 연결 근거가 부족하면 `unknown`을 유지합니다. 일시 비움 판정은 자동 예약이나 자리 권리를 의미하지 않습니다.
- `temporarily_away`를 점유율에 어떻게 반영할지, 언제 다른 상태로 바꿀지는 미정입니다. 별도 상태로 전달해 정책을 구분할 수 있게 합니다.
- 머리 수가 적다고 빈자리가 많다고 판단하지 않습니다. 서 있거나 이동 중인 사람도 좌석 점유와 구분합니다.
- 기둥·모니터·의자 등받이에 가려진 좌석을 빈자리로 처리하지 않습니다. 고정 휴지함을 점유하는 짐으로 오인하지 않는지도 확인합니다.
- 좌석별 결과와 전체 머리 수를 더해 점유 좌석 수를 만들지 않습니다. 다중 카메라의 머리 수 역시 단순 합산하지 않습니다.

## 입력과 출력

### AI가 받을 입력 — 합의 필요

| 입력 | 필요한 내용 |
| --- | --- |
| 영상 또는 프레임 | 카메라 식별자, 관측 시각, 영상 데이터. 수신 방식·프로토콜은 미정 |
| 좌석 정의 | `seat_id`, 좌석 영역, 카메라별 대응 관계, 전체 좌석 수 300 |
| 판정 설정 | 감지 문턱값, 시간 상태 규칙, 혼잡도 기준. 수치와 관리 주체는 미정 |

원본 영상은 AI 분석 서버까지 입력합니다. **원본 프레임을 웹에 전송하는 것을 기본으로 가정하지 않습니다.** 저장·보관 여부도 별도 결정 사항입니다.

### 백엔드에 전달할 결과 초안 — 미구현

아래는 필드 의미를 맞추기 위한 예시이며 실제 관측 결과가 아닙니다. 통신 방식과 API 주소는 아직 정하지 않았습니다.

```json
{
  "facility_id": "engineering5_cafeteria",
  "observed_at": "2026-11-05T09:30:00Z",
  "people_count": null,
  "seat_counts": {
    "available": 0,
    "person_occupied": 0,
    "belongings_occupied": 0,
    "temporarily_away": 0,
    "unknown": 300
  },
  "total_seats": 300,
  "congestion_level": "unknown"
}
```

- `observed_at`: 관측 시각을 UTC ISO 8601로 전달합니다. 결과 전송 시각과 혼동하지 않습니다.
- `people_count`: 인원 추정이 불가능하거나 중복을 해결하지 못하면 `null`입니다. 감지 실패를 0명으로 표현하지 않습니다.
- `seat_counts`: 각 상태의 좌석 수이며 모두 0 이상의 정수입니다. 서로 겹치지 않고 합계는 300입니다. 관측 밖 좌석도 `unknown`으로 포함합니다.
- `congestion_level`: `unknown | low | medium | high`. 기준이나 근거가 불충분하면 `unknown`을 유지합니다.
- 좌석별 상세 결과를 전달한다면 `seat_id`와 상태가 필요합니다. 집계 전 중복 제거와 상세 전송 여부는 백엔드와 합의합니다.
- 혼잡도 등급 산출을 AI와 백엔드 중 어디에서 담당할지도 합의합니다. 같은 기준을 양쪽에서 따로 관리하지 않습니다.

## 학습 환경과 산출물

- 학습 장비: **현재 Mac M4**, Python **3.12**, Ultralytics **8.3.253**, PyTorch **2.9.1**, torchvision **0.24.1**, MPS.
- 공통 `.venv`와 잠금 파일은 저장소 최상위에서 관리합니다. 이 폴더에 별도 가상환경을 만들지 않습니다.
- 학습·평가 명령은 [Mac 학습 안내](../docs/training_mac.txt)를 참고하며 저장소 최상위에서 실행합니다.
- YOLOv8n 기반 실험을 우선 검토하지만 최종 모델·학습 데이터는 아직 확정하지 않았습니다.
- 외부 군중 데이터가 머리 탐지를 지원하더라도 좌석·짐 점유 라벨까지 제공한다고 가정하지 않습니다. 좌석 상태는 현장 자료와 별도 검증이 필요합니다.
- 모델 가중치, 실행 설정, 데이터 분리 기록, 평가 결과를 함께 보관합니다. 데이터·가중치는 현재 Git 제외 대상이며 전달 위치는 팀에서 정합니다.

## 필수 검증 시나리오

| 상황 | 확인할 동작 |
| --- | --- |
| 사람만 앉아 있음 | 해당 좌석을 `person_occupied`로 판정 |
| 사람과 가방이 같은 좌석에 있음 | 1석으로 계산하고 사람 점유 상태로 표현 |
| 사람이 없고 짐이 자리를 차지함 | `belongings_occupied`로 구분 |
| 사용 이력 없이 가방을 들고 배식 중 | 해당 사람에게 임의의 점유 좌석을 배정하지 않음 |
| 기존 사용자가 짐을 들고 잠깐 이동 | 합의한 증거·추적·운영 기준을 충족하면 `temporarily_away`, 근거가 부족한 후보는 `unknown` |
| 기둥·등받이 뒤 좌석 또는 영상 장애 | 확인할 수 없는 좌석을 `available`로 만들지 않음 |
| 여러 영상에서 같은 좌석이 보임 | 동일 `seat_id`를 한 번만 계산 |
| 테이블 위 고정 휴지함 | 짐 점유로 잘못 분류하는지 확인 |
| 멀리 있는 작은 머리·사람 없는 장면 | 누락과 오탐을 각각 측정 |

## 완료 기준

- [ ] 카메라별 관측 구역과 좌석 ID 대응이 정리되어 있다.
- [ ] 데이터·모델 선택 근거와 영상 단위 데이터 분리가 기록되어 있다.
- [ ] 실제 영상에서 인원 추정과 좌석 상태가 별도로 출력된다.
- [ ] 다섯 상태가 상호배타적이며 전체 좌석 수 300과 집계가 일치한다.
- [ ] 위 검증 시나리오와 오류 사례를 확인하고 남겼다.
- [ ] 인원 수 오차, 좌석 상태별 오분류, 처리·전송 지연을 측정했다.
- [ ] 합의한 결과 형식을 백엔드가 수신하며 불확실·관측 실패 상태가 유지된다.
- [ ] 허용 오차와 갱신 기준을 합의하고 실제 측정 결과와 비교했다.

## 현재 실행 현황

**머리 탐지·좌석 상태 분석·전송 코드는 아직 없습니다.** AI-Hub 데이터 변환, 모델 학습, 현장 성능 검증도 아직 실행하지 않았습니다. 환경 점검 성공은 모델 학습이나 서비스 정확도 검증 완료를 의미하지 않습니다.

이 폴더에서 바로 실행할 AI 서비스 명령은 없으며, 구현이 추가되면 입력 방법과 실행 명령을 갱신합니다.
