# Android 앱 작업 안내

담당: **김민정** — 공유된 기획서 초안 기준

5공학관 식당 **300석**의 현재 상태를 방문 전에 확인하는 **Android 앱**을 담당합니다. 기존 `frontend` 폴더명을 유지합니다. 대상 시설은 한 곳이며 도서관·스포츠센터·다른 시설 목록은 현재 범위에 포함하지 않습니다.

**현재는 작업 안내만 있습니다.** Android를 대상으로 한다는 방향은 확정됐지만 프레임워크, 개발 환경, UI 코드, API 연결, 푸시 알림과 배포는 아직 구현되지 않았습니다. 아래 내용은 개발할 항목과 협의안입니다.

전체 기획과 환경 설정은 [프로젝트 README](../README.md), 연동 사항은 [백엔드 안내](../backend/README.md), 상태 판정 원칙은 [AI 안내](../ai/README.md)를 참고합니다.

## 담당 범위

- 식당 전체 현황과 필요한 경우 구역별 상태 표시
- 관측 인원, 좌석 상태, 마지막 갱신 시각과 정보 지연 표시
- 백엔드 조회 API 연결, 초기 로딩·오류·미수신 처리
- Android 화면과 알림 권한·수신 설정 구성
- 앱을 보고 있지 않을 때도 혼잡 단계 변화 푸시를 받을 수 있도록 연동
- Android 실기기에서 조회·알림 확인과 앱 배포 준비

모델 추론, 좌석 점유 계산과 혼잡도 임계값 결정은 앱에서 독자적으로 구현하지 않습니다. 팀이 합의한 서버 결과를 표시하며, 데이터가 없을 때 임의의 인원·빈자리 수를 만들지 않습니다.

## 앱에 제공할 기능과 정보

| --- | --- | --- |

| 현재 혼잡도 | 원활·보통·혼잡 또는 확인 불가 | 임계값은 미정. 서버와 합의한 상태를 표시 |

| 좌석 상태 내역 | 사람 점유, 짐 점유, 일시 비움, 확인 불가 | 같은 좌석을 여러 상태에 중복 합산하지 않음 |
| 현재 감지 인원 | `people_count`와 관측 범위 | 일부 구역 값이면 식당 전체 인원처럼 표시하지 않음 |
| 최신성 | 관측 시각, 수신·연결 상태 | 과거 값을 현재 실시간 값으로 오해하지 않도록 표시 |
| 알림 설정 | 수신 ON/OFF, 변화 방향, 시스템 알림 권한 | 앱 설정과 Android 권한을 구분하여 표시 |
| 구역별 보기 | 등록한 구역별 좌석과 상태 | 실제 구역 배치·좌석 수가 확정된 뒤 연결 |

색상만으로 상태를 구분하지 않고 상태명과 수치를 함께 표시합니다. 좌석 배치가 확정되지 않았을 때 실제 평면도처럼 보이는 임의의 좌석도를 만들지 않습니다.

## 작업 순서

1. Android 프레임워크·프로젝트 구조·개발 도구 버전과 실기기 테스트 방법을 정합니다.
2. 300석, 다섯 좌석 상태, 인원, 시각, 관측 범위를 보여줄 기본 화면을 구성합니다.
3. 예시 데이터임을 명시한 개발용 데이터로 정상·로딩·미수신·오류·부분 관측 화면을 만듭니다.
4. 백엔드가 확정한 조회 API에 연결합니다. 응답 형식과 갱신 방식을 함께 확정합니다.
5. 백엔드와 푸시 방식, 기기 등록·수신 설정 API, 단계 변화 이벤트를 합의합니다.
6. 알림 권한·수신 설정·알림 탭 후 최신 현황 조회를 연결합니다.
7. 실제 또는 재생 영상의 분석 결과와 실기기 푸시를 통합 점검합니다.
8. 앱 빌드·배포 방법을 문서화합니다. 구역별 보기와 캐릭터 효과는 기본 기능 이후 진행합니다.

## 백엔드와 합의할 입력

아래는 **연동 초안**입니다. 실제 API는 아직 없습니다. 조회 경로 제안은 `GET /api/facilities/engineering5_cafeteria/status`입니다.

| 필드 | 화면에서의 사용 |
| --- | --- |
| `facility_id` | 식당 식별자. 제안값 `engineering5_cafeteria` |
| `observed_at` | 영상 관측 시각. UTC ISO 8601을 받아 KST로 명확하게 표시 |
| `total_seats` | 전체 좌석 300 |
| `people_count` | 정수면 감지 인원, `null`이면 확인 불가. 0과 구분 |
| `seat_counts` | `available`, `person_occupied`, `belongings_occupied`, `temporarily_away`, `unknown` |
| `congestion_level` | `low` → 원활, `medium` → 보통, `high` → 혼잡, `unknown` → 확인 불가 |

전체 식당의 좌석 상태를 표현할 때 `seat_counts`의 합계는 300이어야 하며 미관측 좌석은 `unknown`으로 전달받습니다. 필요한 값이 누락됐거나 합계가 맞지 않으면 앱이 나머지를 빈자리로 채우지 않고 데이터 상태를 표시합니다.

부분 관측 구역, 마지막 수신 시각, 정보 만료 기준과 연결 상태 필드는 추가 협의 대상입니다. 화면 갱신 방식과 주기 역시 아직 미정입니다.

### 개발용 예시

다음 값은 **화면 개발용 예시이며 실제 관측 결과가 아닙니다.**

```json
{
  "facility_id": "engineering5_cafeteria",
  "observed_at": "2026-11-05T09:30:00Z",
  "total_seats": 300,
  "people_count": null,
  "seat_counts": {
    "available": 60,
    "person_occupied": 170,
    "belongings_occupied": 20,
    "temporarily_away": 10,
    "unknown": 40
  },
  "congestion_level": "unknown"
}
```

이 예시는 바로 이용 가능한 좌석 60석, 확인 불가 40석, 인원 확인 불가로 표시합니다. 전체 점유율이나 혼잡 단계를 임의로 계산하지 않습니다. `temporarily_away`는 상태 표현을 시험하기 위한 값이며 실제 판정·유예 정책은 별도 확정 대상입니다.

## 상황별 화면 처리

| 상황 | 화면 처리 |
| --- | --- |
| 최초 접속 후 아직 응답 없음 | 로딩 또는 관측 대기. 0명·빈자리 300석으로 초기화하지 않음 |
| 인원 0이 정상적으로 관측됨 | 0명 표시. 좌석 상태는 별도로 표시 |
| 인원 값이 `null` | 인원 확인 불가 표시 |
| 짐만 있는 좌석 | 짐 점유에 포함, 바로 이용 가능한 좌석에서 제외 |
| 일시 비움 | 일시 비움으로 표시. 예약 완료나 곧 복귀한다는 표현을 사용하지 않음 |
| 일부 좌석이 가려짐 | 확인 불가 수와 관측 범위를 표시 |
| 응답 지연·연결 중단 | 마지막 값을 표시한다면 해당 시각과 지연 상태를 함께 표시 |
| 녹화 영상이나 개발용 데이터 사용 | 재생 영상 또는 예시 데이터임을 눈에 띄게 표시 |

다섯 좌석 상태는 상호 배타적입니다. 사람과 짐이 함께 있는 좌석도 한 석이며, 짐을 들고 이동한다는 이유만으로 좌석 점유를 만들지 않습니다. 감지 인원과 좌석 수를 더하여 새로운 이용 인원을 만들지 않습니다.

`temporarily_away`는 합의된 증거·추적·운영 기준을 충족한 일시 비움 상태입니다. 근거가 부족한 후보는 `unknown`으로 유지하며, 앱이 자리 소유권이나 자동 예약을 부여하지 않습니다. 실제 판정·유예 정책은 미정입니다.

## 혼잡 단계 변화 알림

앱을 보고 있지 않을 때도 선택한 방향의 단계 변화를 푸시로 알리는 기능을 개발합니다. 현재 알림 전송·수신 구현은 없습니다.

| 설정 | 예정 동작 |
| --- | --- |
| 수신 ON/OFF | 사용자가 알림 수신을 켜거나 끔. 기본값은 미정 |
| 원활해질 때 | 혼잡 → 보통, 보통 → 원활, 혼잡 → 원활 변화 알림 |
| 혼잡해질 때 | 원활 → 보통, 보통 → 혼잡, 원활 → 혼잡 변화 알림 |
| 양방향 | 위 두 방향 모두 알림. 방향 기본값은 미정 |

### 권한과 사용자 설정

- 사용자가 알림 기능을 선택할 때 목적을 설명하고 필요한 권한을 요청합니다.
- Android 13 이상에서는 일반 알림에 `POST_NOTIFICATIONS` 런타임 권한이 필요합니다. [Android 공식 안내](https://developer.android.com/develop/ui/compose/notifications/notification-permission)
- 권한을 거부해도 식당 현황 조회는 사용할 수 있어야 합니다.
- 앱의 수신 설정과 Android 시스템 알림 허용 상태를 각각 표시합니다. 앱 설정이 ON이어도 시스템에서 차단됐다면 수신 가능으로 표시하지 않습니다.
- 수신 설정 변경을 백엔드와 동기화합니다. 요청 실패 시 저장 완료로 표시하지 않습니다.

### 서버와 앱의 역할

서버가 안정화된 단계 변화와 알림 발송 대상을 결정합니다. 앱 화면에서 받은 수치를 비교해 별도의 혼잡도나 푸시 이벤트를 만들지 않습니다.

- 단계가 잠깐 흔들릴 때의 확정 기준, 중복 억제, 재알림 간격은 서버와 합의하며 구체 시간은 미정입니다.
- 최초 유효 관측은 비교 기준으로 사용합니다. 이전 상태 없이 상승·하락 알림을 만들지 않습니다.
- `unknown`이나 오래된 정보는 원활·혼잡으로 간주하지 않습니다. 정상 정보 복구 후 비교 기준을 다시 잡는 정책도 서버에서 합의합니다.
- 알림을 누르면 식당 현황 화면을 열고 최신 상태를 다시 조회합니다. 알림의 과거 값으로 현재 현황을 덮어쓰지 않습니다.
- 최신 조회가 실패하면 마지막 확인 시각과 실패 상태를 표시합니다. 알림에도 변화 시각을 확인할 수 있도록 구성합니다.

푸시 수단은 **FCM을 후보로 검토 중**이며 아직 채택·설정되지 않았습니다. 채택 시 공식 Android 연동 절차를 따릅니다. [FCM Android 시작 안내](https://firebase.google.com/docs/cloud-messaging/android/get-started)

백엔드와 기기 등록 토큰의 최초 등록·갱신, 수신 ON/OFF·방향 동기화 API를 합의해야 합니다. 이벤트 식별자, 이전·새 단계, 관측 시각 등 알림 데이터 형식도 미정입니다. 중복·지연 알림 처리 기준을 함께 정합니다.

FCM 발송용 서버 인증 정보·서비스 계정 키, 분석 결과 수신용 비밀 토큰과 Cloudflare 계정 토큰을 앱 코드나 배포 파일에 넣지 않습니다.

| 시나리오 | 확인할 동작 |
| --- | --- |
| 단계 상승·하락과 두 단계 직접 이동 | 선택한 방향에 맞는 이벤트만 수신 |
| 최초 관측·확인 불가·오래된 정보·정상 복구 | 합의한 비교 기준 정책 적용, 잘못된 원활 알림 방지 |
| 권한 거부 또는 시스템에서 알림 차단 | 현황 조회 유지, 알림 불가 상태 안내 |
| 앱 수신 OFF 또는 방향 변경 | 서버 설정 반영과 이후 발송 조건 확인 |
| 동일 이벤트 중복·늦게 도착한 알림 | 중복 억제와 오래된 정보 구분 |
| 앱을 보고 있지 않은 Android 실기기 | 백그라운드 수신과 알림 표시 확인 |
| 알림 탭·이후 조회 실패 | 최신 상태 재조회, 실패 시 시각·연결 상태 표시 |
| 사람과 짐 동시 점유·이동·복귀·가림 | 좌석 중복 합산 없이 다섯 상태를 표시 |

알림 전달 시점과 백그라운드 동작은 실제 기기에서 확인합니다. 실기기 검증 전 모든 앱 상태에서 즉시 수신된다고 안내하지 않습니다.

## 추가 기능 범위

- 사람 캐릭터 효과는 혼잡도를 표현하는 보조 장치입니다. 아이콘 수와 실제 사람 수의 관계를 혼동하지 않도록 표시합니다.
- 다른 시설을 추천하는 기능은 제외합니다. 식당 내 여유 구역 안내는 후속 제안입니다.
- 방문 시간 예측은 기록 데이터와 예측 API가 확보된 뒤 검토합니다. 임의 곡선을 실제 예측 결과로 표시하지 않습니다.
- 원본 카메라 영상을 일반 사용자에게 보여주는 기능은 현재 계획에 포함하지 않습니다.

## 개발 환경과 배포

- Android 대상만 확정됐습니다. 네이티브 Android(Kotlin), Flutter, React Native 등 구현 방식은 미정입니다.
- 선택한 프레임워크에 맞는 Android SDK, JDK·Gradle 등 도구 버전과 프로젝트 구조를 정해야 합니다. Android 개발 환경이 준비됐다고 가정하지 않습니다.
- 저장소의 Python 가상환경은 AI 작업용이며 Android 앱 빌드 환경을 대신하지 않습니다.
- 루트의 `npm ci`, `npm run cf:version`은 Cloudflare 백엔드 도구 준비·확인 명령이며 **Android 앱 빌드 명령이 아닙니다.**
- 앱 설치·실행·빌드 명령은 도구 선택과 검증 후 여기에 추가합니다. APK 공유 등 배포 방식도 아직 미정입니다.
- Cloudflare는 백엔드 API 용도로 협의합니다. Android 앱 배포 방식과 구분하고, 앱에서 접근할 API 주소를 백엔드와 합의합니다.
